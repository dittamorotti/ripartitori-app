Struttura generale del file XML

Il file XML QUNDIS contiene le letture di uno o più ripartitori di calore. La struttura è gerarchica:

<siemeca>
→
<communicator>
+
<measuredev> × N
→
<datapoint> × M
Nota: Ogni <measuredev> rappresenta un singolo ripartitore. Il campo chiave di collegamento con il database è <identnr> (matricola).
🔢
Versioni del formato XML
V1.0 — Base
  • Struttura minima
  • Solo dati correnti
  • Nessuno storico mensile
V1.1 — Standard
  • Storico mensile (storagenr 8–25)

Campi del dispositivo <measuredev>
Tag XML Nome italiano Tipo Descrizione
identnr Matricola Chiave Numero seriale univoco del ripartitore. Collegamento principale con il database anagrafico.
date Data lettura Testo Data dell'ultima lettura nel formato dd.mm.yy (es. 01.06.26)
time Ora lettura Testo Ora dell'ultima lettura nel formato hh:mm:ss
errorflags Codice errore parsing Numero 0 = nessun errore. Valori: 1=chiave mancante, 2=dati incompleti, 8=errore protocollo. Vedi tabella errori.
errordate Data primo errore Data Data del primo errore permanente rilevato. Formato dd.mm.yy. Vuoto se nessun errore.
status Stato dispositivo Numero 0 = OK. Altri valori indicano anomalie hardware del ripartitore (es. 40=guasto sensore, 80=fuori range).
powerstatus Stato batteria Testo Percentuale batteria (es. "78 %") o "Ext.Power" se alimentato esternamente. Può essere assente.
manufact Codice produttore Numero 17555 = QUNDIS, 12901 = LSE. Identifica il produttore del dispositivo fisico.
version Versione firmware Testo Versione del firmware installato nel ripartitore.
accessnr Numero accesso Numero Contatore incrementale ad ogni trasmissione. Utile per rilevare letture mancanti.
subnet Sottorete Numero Indirizzo della sottorete del sistema di comunicazione wireless.
receiver Nodo ricevente Numero Identificativo del gateway/concentratore che ha ricevuto la trasmissione.
signature Firma / Encryption Numero 0 = nessuna cifratura, 5 = AES128, 7 = AES128+CMAC. Indica il metodo di sicurezza usato.

Misurazioni <datapoint> — Valori H.C.A.

Ogni <datapoint> contiene un'unità di misura. I valori H.C.A. (Heat Cost Allocator) sono quelli principali per la ripartizione del calore.

Campi di ogni datapoint

TagDescrizione
storagenr 0 = valore corrente (lettura del giorno). 1–N = valori storici mensili. Più alto = più recente. In V1.1 lo storico parte da 8.
value Il valore numerico della misurazione (es. 731).
dimension Unità di misura. H.C.A. = ripartitore calore, date = data associata al valore storico, datetime = data+ora trasmissione, Fabrication no = numero fabbricazione.
tariff Tariffa associata (solitamente 0).
subunit Sotto-unità (solitamente 0).

Logica dello storico mensile

storagenrSignificatoNote
0 Valore corrente (data lettura) Sempre presente
20 (più alto) -1 mese (mese precedente) Il numero più alto nello storico è il più recente
19 -2 mesi –
18 -3 mesi –
... ... Fino a 12 mesi di storico
8 (più basso) -12 mesi (il più vecchio) In V1.1 lo storico inizia da 8
⚠️ Reset annuale: I ripartitori si azzerano il 1 ottobre di ogni anno. I valori storici precedenti al 1 ottobre dell'anno corrente (o precedente se siamo prima di ottobre) non sono comparabili con quelli dell'anno in corso e vengono esclusi automaticamente dall'applicazione.
⚠️
Codici errore — errorflags

Il campo errorflags indica problemi nel parsing o nella trasmissione dati. Non descrive guasti hardware (quelli sono in status).

ValoreSignificatoAzione consigliata
0Nessun errore—
1Chiave di decriptazione mancanteVerificare la configurazione del gateway
2Dati incompleti / troncatiRifare la lettura
4Errore CRC (checksum)Interferenza radio, rifare la lettura
8Errore protocolloVersione firmware incompatibile
16Timeout comunicazioneDispositivo fuori portata radio
32Errore autenticazioneChiave AES non corretta
🔧
Codici stato hardware — status

Il campo status descrive lo stato fisico del ripartitore.

ValoreSignificato
0OK — dispositivo funzionante
40Guasto sensore temperatura
80Valore fuori range (temperatura anomala)
120Guasto sensore + fuori range
160Dispositivo manomesso o rimosso

Logica storico mensile nell'app

OperazioneDettaglio
Ordinamentostoragenr decrescente → il valore con storagenr più alto è il più recente (-1 mese)
Date calcolateL'app calcola le date di fine mese a ritroso dalla data di lettura del dispositivo (non usa le date dell'XML che spesso mancano)
Filtro resetVengono esclusi i valori con data calcolata precedente al 1 ottobre dell'anno di reset
Max storicoVengono mostrati al massimo 12 mesi di storico
Confronto anno prec.Viene cercato il valore dello stesso mese dell'anno precedente (es. lettura di giugno 2026 → cerca giugno 2025)
